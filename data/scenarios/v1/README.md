# LOW SKY 합성 시나리오 데이터셋 v1

실제 작전 재현이 아닌 관측과 판단 과정의 데모다. 12개의 반복 변형을 **서로 다른 대표 장면 2개와 모니터링 부하 시험 1개**로 줄였다. 비행체 수는 합성 장면 구성 가정이며 실측 공격 규모를 뜻하지 않는다. 적대 의도·무기 효과·공격 경로 최적화는 모델링하지 않는다.

| 케이스 | 구성 | 검토할 상황 |
| --- | --- | --- |
| case_001 | 비행체 12개, 관측 서사 | 첫 수신 전 빈 화면 → 순차 탐지 → 지연된 두 번째 채널 → 교차 확인 |
| case_002 | 비행체 24개, 관측 서사 | 혼재된 배경 → 6개 대상의 표식 상충 → 양측 근거 보존 → 재확인 |
| case_003 | 비행체 240개, 유일한 부하 시험 | 다수 대상 표시 → 채널 B 단절 → 마지막 근거 유지 → 채널 복구 |

각 장면은 180초, 관측 채널 2개, 10초 간격으로 구성된다. 총 합성 관측 6,876개와 평가 체크포인트 1,380개다. 모두 development 장면이며 독립 보류 평가나 실전 탐지 성능을 주장하지 않는다. case_003의 240개는 검토 대기열·렌더링 부하를 위한 합성 수량이다. 경로는 기존 화면 범위에 머무는 단순 격자로 구성되며 실제 공격 규모·편대·전술을 나타내지 않는다.

## 가상 센서 상태 부하

`data/sensor_fleet_demo.json`과 `tools/sensor_fleet.py`는 모든 케이스에 논리 센서 240개(인원 휴대폰·시설 센서·민간 휴대폰·고정 휴대폰 각 60개)의 상태만 제공한다. 실제 설치 수량이나 탐지 범위를 뜻하지 않으며 3D의 폰 폴 2개, 조기 신호 관측, 채널 A/B와 독립적이다. 하트비트로 비행체 탐지를 만들지 않는다.

- 10초 간격 하트비트는 1초 뒤 수신된다. 첫 수신 전에는 `waiting`이며 수신·관측 시각이 지난 상태만 공개된다.
- case_003의 시설 센서는 60~120초 관측에서 `offline`을 보고하며 61초부터 표시한다. 고정 휴대폰 그룹은 같은 기간 보고를 보내지 않아 마지막 50초 관측이 20초를 초과하면 `stale`이 된다.
- 두 그룹은 130초 관측이 131초에 수신되면 `online`으로 복구된다. 단절 원인은 `unknown`으로 두며 파손·전파방해 등의 원인을 추정하지 않는다.
- 응답은 센서별 최신 수신 상태 240개와 그룹별 합계로 제한한다. 미래 단절 일정이나 객체 ID·위치·탐지 근거는 포함하지 않는다. 가상 센서 상태 변화는 검토 대기열에 새 항적을 만들지 않는다.

## 시간과 사건

- 00:00~00:09: 수신된 객체 ID·관측·객체별 공지가 없다. 제작자용 Godot 화면에서는 실제 합성 움직임을 볼 수 있다.
- 00:10~01:00: 객체들이 여섯 묶음으로 순차 수신된다. 첫 채널 B 보고는 관측보다 4초 늦다. 첫 보고만으로 정체나 적대성을 확정하지 않는다.
- 00:40: 일부 채널 B 보고가 15초 늦게 도착한다. 더 최신인 00:50 보고 이후 도착해도 최신 관측을 덮어쓰지 않는다.
- 01:00~02:00: case_002에서는 6개 객체에 대해 채널 B 표식이 다르다. case_003에서는 채널 B가 오프라인이다.
- 01:30: 뒤늦게 공개된 검토 공지가 수신된다. 이전 스냅샷에서는 접근할 수 없다.
- 02:10: case_002 표식 일치와 case_003 채널 B 보고가 복구된다.
- 03:00: 종료. 근거 참조, 불확실성, 단절·복구 판단을 검토한다.

민간 조기 신호 피드는 별도 합성 데이터이며 이 관측 데이터의 객체와 자동 연결되지 않는다. 이 데이터의 채널 A/B는 물리 레이더·음향 성능 모델이 아니다. `marker_label`은 합성 표식이며 민간·적대 분류가 아니다.

상세 문서의 관측·검토 맥락은 `data/situation_review.json`에서 공유 시계로 재생한다. 문서의 작전 시간·공격 순서·성과 수치를 복제하지 않는다. 검토 기록은 사용자의 실제 입력만 집계한다. 별도 `data/early_warning_demo.json`에는 커뮤니티 3구역과 폴 장착 폰 시범 구역이 있으며 대상 항적과 자동 결합하지 않는다.

## 파일과 공개 범위

| 파일 | 소비자와 내용 |
| --- | --- |
| `manifest.json` | 선택기·평가 도구: 케이스와 정보 조건 |
| `briefings.json` | 운영자가 요청한 미래 사건 포함 시나리오 설명; 영어·한국어 제공 |
| `scene.json` | Godot 공통 시설; `data/site_layout.json`에서 재생성 |
| `cases/<id>/world.json` | 제작자·3D 재생: 전체 실제 경로와 시각 에셋 |
| `cases/<id>/public.json` | 입력 추출기: 전체 시간대 관측·상태·공지 |
| `evaluation/<id>.json` | 검토자: 70·90·120·150·180초의 객체별 기대 정보 상태 |

**`public.json` 전체도 에이전트 입력으로 제공하지 않는다.** `snapshot`으로 현재 재생 시점까지 수신된 관측만 전달한다. `object_ids`도 최소 한 번 수신된 객체로 제한한다. 객체별 공지는 공개 시각이 지났고 참조한 모든 객체가 수신된 후에만 제공한다. ID만 지우고 자유 텍스트를 남겨 미탐지 객체가 노출되는 것을 피한다. 시나리오 설명·실제 경로·평가 정답은 입력에서 제외한다. 파일 분리는 접근 제어가 아니므로 향후 에이전트 도구에도 이 경계를 유지한다.

## 데이터 계약

- `schema_version`: `1.0`. 시간은 시작부터 정수 밀리초다.
- 좌표: `[x,y,z]`, Y-up, 미터. X는 동쪽, Z는 남쪽이다. 공통 가상 부지 배치를 사용하며 항공역학은 구현하지 않는다.
- 경로: 키프레임 사이를 선형 보간한다. 실제 드론 모델 폭은 기본 0.6m이며 제작자용 화면 표식은 별도다.
- 관측: ID, 객체·채널 ID, 관측·수신 시각, 위치, 표식. 두 시각 모두 현재 시각 이하여야 공개한다.
- 채널 상태: `online`/`offline`. 관측과 채널 상태는 45초를 초과하면 오래된 근거로 처리한다.
- 비교: 같은 시각의 두 최신 관측이 일치해야 `consistent`. 다른 시각이면 `not_comparable`, 표식이 다르면 `contradictory`, 채널 또는 최신 근거가 부족하면 `missing`이다.
- 단절 때 마지막 위치를 보존하며 미래 위치를 예측해 표시하지 않는다. 처음부터 보고되지 않은 대상은 표시하지 않는다.
- 평가 기대값은 사건 계약에서 작성하며 기준선 계산 결과를 복사해서 만들지 않는다. 적대 의도·미관측 확인·미래 근거 주장은 금지한다.

## 생성과 검증

Python 표준 라이브러리만 사용한다.

```sh
python3 tools/scenario_dataset.py build
python3 tools/scenario_dataset.py validate
python3 -m unittest discover -s tests -v
python3 tools/scenario_dataset.py snapshot --case case_003 --at-ms 90000 --output /tmp/lowsky-agent-input.json
```

`build`는 생성 JSON을 다시 쓰고 이전 case_004~012의 알려진 생성 파일만 제거한다. 같은 코드·시설 배치로 재생성하면 동일 바이트가 나온다. 원본 문서는 생성 대상이 아니다. 스냅샷 SHA-256은 입력 식별자이며 인증 서명이 아니다.

실제 센서별 검증 데이터, 독립 평가 시나리오, 사용자 검토 결과, 모델 실행 결과는 아직 없다. 지금의 대상 수와 지연·최신성 기준은 장면 계약이며 경험적 성능 근거가 아니다.
