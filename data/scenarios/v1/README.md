# LOW SKY 합성 시나리오 데이터셋 v1

Godot 3D 장면 재생과 에이전트의 근거 설명을 시험하기 위한 작은 초기 데이터셋이다. 실제 기지, 항공기 운항, 센서 측정 자료는 포함하지 않는다. 모델 학습용 대규모 데이터셋이나 실전 성능 평가 자료가 아니다.

## 구성

| 항목 | 수량 |
| --- | --- |
| 기본 장면 | 4 |
| 정보 조건 | 일치·충돌·결측 3종 |
| 실행 케이스 | 12 |
| 합성 관측 | 324 |
| 평가 체크포인트 | 144 |
| 개발 / 보류 평가 케이스 | 6 / 6 |

각 케이스는 120초이며 이동 객체 3개, 관측 채널 2개, 30초 간격의 이벤트를 가진다. 같은 기본 장면의 세 갈래는 동일한 3D 경로를 공유한다. 기본 장면이 다른 분할에 걸치지 않게 분리했다. 다만 모두 같은 생성 규칙에서 나온 작은 변형이므로 보류 평가 통과를 새로운 상황에 대한 일반화 성능으로 해석하면 안 된다.

## 파일과 접근 범위

| 파일 | 소비자 | 내용 |
| --- | --- | --- |
| `manifest.json` | 시나리오 선택기·평가 도구 | 케이스 ID, 장면 그룹, 분할, 정보 조건 |
| `scene.json` | Godot | 공통 환경 배치, 에셋 ID, 좌표계 |
| `cases/<id>/world.json` | 제작자 보기·재생 엔진 | 객체의 실제 경로 키프레임, 시각 에셋 매핑 |
| `cases/<id>/public.json` | 입력 추출기 | 전체 시간대의 관측·채널 상태·가상 공지 |
| `evaluation/<id>.json` | 평가 도구·검토자 | 기대 정보 상태와 설명 검토 항목 |

**`public.json`도 파일 전체를 에이전트에게 주면 안 된다.** 전체 타임라인이 들어 있다. 반드시 `snapshot` 명령으로 현재 시각까지 알려진 내용만 추출한다. `manifest.json`의 정보 조건, `world.json`의 실제 경로와 표시 정답, 평가 파일은 에이전트 입력에서 제외한다.

파일 분리는 접근 제어 자체가 아니다. 향후 Deep Agents를 연결할 때는 추출한 스냅샷만 읽는 도구를 제공해야 한다. 이 저장소 전체를 에이전트 파일시스템으로 연결하지 않는다.

## 데이터 계약

- `schema_version`: `1.0`. 시간은 시나리오 시작부터의 정수 밀리초다.
- 좌표: `[x, y, z]`, 오른손 좌표계, Y가 위쪽. `fictional_scene_unit`은 가상 장면 단위이며 실측 미터가 아니다.
- 경로: 인접 키프레임 사이를 선형 보간한다. 항공역학이나 센서 광학 모델은 없다.
- 관측: `id`, `object_id`, `source_id`, `observed_at_ms`, `available_at_ms`, `position`, `marker_label`.
- 채널 상태: `id`, `source_id`, 관측·도착 시각, `online` 또는 `offline`.
- 맥락: `id`, `published_at_ms`, 유효 시간 구간, 관련 객체 ID, 가상 공지문.
- 관측은 관측 시각과 도착 시각 모두 재생 시각 이하여야 공개한다. 맥락은 공개 시각으로 제한한다. 이미 공개된 미래 일정은 표시할 수 있다.
- 근거 ID는 케이스 안에서 고유하다. 실행 결과에는 `snapshot_id`와 실행 ID를 함께 저장해야 다른 실행의 근거와 혼동하지 않는다.

현재 `marker_label`은 표시 표식의 문자열을 의미한다. 두 합성 채널이 같은 시각에 같은 표식을 보고했는지 비교하는 데이터 품질 실험이다. 센서별 실제 성능이나 객체의 위험성·적대성 분류를 뜻하지 않는다.

## 세 갈래

1. **일치:** 두 채널의 동일 시각 표식 보고가 일치한다.
2. **충돌:** 60초부터 선택 객체 하나에 대해 채널 B가 다른 표식을 보고한다. 평가에서는 어느 채널이 맞는지 단정하는 대신 상충하는 두 근거를 제시해야 한다.
3. **결측:** 60초부터 채널 B 전체가 오프라인이며 새 관측이 없다. 30초의 마지막 기록은 남지만 최신 확인 자료로 승격하지 않는다.

규칙 기반 기준선은 채널 상태와 관측의 최신성을 먼저 확인한다. 45초를 초과한 기록은 오래된 것으로 처리하고, 서로 다른 시각의 관측은 `not_comparable`로 처리한다. 이 기준은 데모용 계약이며 실제 센서 기준이 아니다.

90초에는 60초 이후에 관한 메모가 뒤늦게 공개된다. 이 메모가 60초 스냅샷에 들어가지 않는지 테스트한다. 각 평가 시점은 30·60·90·120초이며 객체별로 기대 상태를 기록한다.

## 생성과 검증

저장소 루트에서 Python 3.12의 표준 라이브러리만 사용한다.

```sh
python3 tools/scenario_dataset.py build
python3 tools/scenario_dataset.py validate
python3 -m unittest discover -s tests -v
python3 tools/scenario_dataset.py snapshot --case case_003 --at-ms 90000 --output /tmp/lowsky-agent-input.json
```

`build`는 생성된 JSON 파일을 다시 쓴다. 직접 수정한 데이터는 별도 버전이나 폴더로 보관한다. 같은 코드로 다시 생성하면 동일한 바이트가 나온다. 스냅샷의 SHA-256은 동일 입력 비교를 위한 식별자이며 인증 서명은 아니다.

검증기는 이 v1 데이터의 필수 참조, 시간 순서, 좌표, 케이스 수, 분할, 기대 상태를 검사한다. 범용 JSON Schema 검증기는 아니다. 테스트는 미래 정보 제외, 늦은 도착, 공개 필드 제한, 오래된 자료, 분할 누출 및 재생성 일치 등을 확인한다.

## 에셋 교체

`scene.json`과 `world.json`은 파일 경로 대신 `asset_id`를 사용한다. 임시 GLB 매핑은 `godot/assets/manifest.json`에 있다. 기본 Godot 미리보기에서는 `preview.gd`의 `asset_instance`가 지형·격납고·관제탑·보조 건물을 상세 절차 모델로 교체한다. `--stylized`에서는 Kenney 후보 모델을, `--blockout`에서는 임시 GLB를 사용한다. PBR 재질과 배경용 항공기는 관측 데이터에 들어가지 않는다. 에셋 교체 시 객체 ID와 관측 기록은 유지한다. 외부 모델의 스케일과 바닥 피벗은 화면 쪽에서 정규화한다.

## 남은 데이터 작업

- 더 다양한 가상 일정·문장·지연 패턴과 독립적으로 작성한 평가 장면 확대.
- 설명 품질의 사람 검토 및 실제 모델 실행 결과 수집.
- 7개 필드의 사람 검토 기록 수집. 현재 데이터에는 가짜 사용자 검토 결과를 넣지 않았다.
- 3D 화면의 모습과 에이전트가 아는 관측 범위를 구분하는 운영 화면 구현.
