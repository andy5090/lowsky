# LOW SKY 시나리오 중심 MVP 구상

작성일: 2026-10-10

이 문서는 `LOW_SKY_team_brief.docx`를 바탕으로 구현 범위를 줄인 제안이다. 사용자가 밝힌 방향은 시나리오 중심 축약, 게임 엔진을 이용한 시뮬레이션, Deep Agents 등을 이용한 에이전트 시스템이다. 후속 답변에서 **3D 시뮬레이션 + 시나리오 데모 + 에이전트 실험**을 함께 첫 결과물의 목표로 선택했다. 아래의 객체 수, 재생 시간, 역할 분리는 초기 제안이다.

## 확정한 배경과 아트 방향

2026-10-10 사용자 수정에 따라 **가상의 공군 기지**로 확정했다. 실제 기지 선정·측량·복제는 하지 않는다. 건물·활주로·지형은 시나리오에 맞게 독자 배치하고, 표현은 **실사 지향**으로 유지한다. 현실적인 외형과 재질은 외부 에셋 및 자체 모델링으로 보강한다. 현재 지형은 절차 생성이며 Google Maps/Earth 연결은 없다.

배경 참고 지역은 사용자의 “미정, 혹은 우크라이나” 답변에 따라 **미확정이며 우크라이나가 후보**다. 사용자 요청에 따라 넓은 평야, 완만한 기복, 농경지 패턴과 수목대를 조합한 테스트 지형 하나를 적용했다. 특정 지역의 정확한 재현으로 간주하지 않으며 실제 기지·운영 상황을 시나리오에 연결하지 않는다. Godot의 기본 장면에서 실행되고 T 키로 기존 구릉 지형과 비교한다. 지형 전환은 시나리오 상태를 변경하지 않는다. 수목은 절차 모델이며 최종 식생 에셋은 추후 보강한다.

배경 고도 자료 후보인 [Copernicus DEM GLO-30](https://dataspace.copernicus.eu/explore-data/data-collections/copernicus-contributing-missions/collections-description/COP-DEM)은 공식적으로 전 세계 육지의 30m 격자 자료를 제공한다. 건물·식생을 포함하는 DSM이므로, 선택 지역의 타일을 확인한 뒤 큰 지형 윤곽을 참고하는 용도로 검토한다. 기지 근경의 지면·건물·식생은 별도 제작한다. 현재 특정 타일을 선정하거나 내려받지는 않았다.

## 목표

가상 비행장 3D 장면에서 관측 정보가 달라질 때, 시스템이 무엇을 알고 무엇을 모르는지 설명하고 사람이 검토한 내용을 기록하는 훈련용 데모를 만든다. 하나의 장면을 정보 일치·충돌·결측의 세 갈래로 재생하고, 동일한 입력으로 단일 에이전트와 역할을 나눈 에이전트 구성을 비교한다.

세 목표는 같은 데이터와 화면을 공유한다. 3D 장면에서 사건을 재생하고, 시나리오가 관측 정보의 변화를 만들며, 실험 화면이 에이전트별 설명과 근거를 비교한다.

성공 기준은 센서 이상이 발생했을 때 화면, 근거 카드, 검토 기록이 서로 일치하는 것이다. 실제 표적 판별, 위협 우선순위 산정, 무기 배정, 교전 권고 및 제어는 이 MVP의 범위에 포함하지 않는다.

## 원문에서 유지하거나 축소할 내용

| 원문 요소 | MVP 제안 |
| --- | --- |
| 관찰·의심·검증 구분 | 문장별 관측 사실·해석·확인 근거를 구분하고 출처를 연결 |
| 판단 전 맥락 확인 | 사전 작성한 가상 일정과 공지 몇 개를 조회 |
| 모순과 결측의 명시 | 정보 일치·충돌·결측 상태를 규칙으로 계산 |
| 제약 확인 | 일정 중첩 등 검토에 필요한 맥락을 표시 |
| 7개 필드 기록 | 원문의 필드를 유지하되 사람이 내린 결정은 검토 결과로 기록 |
| 기지 하나·시나리오 하나·갈래 셋 | 그대로 유지 |
| 실제 웹 추출 및 센서 연동 | 로컬 합성 데이터로 대체 |
| 디코이·위협 분류와 대응 수단 배정 | 제외 |

원문에 기존 파이프라인과 스키마가 있다고 서술되어 있지만 현재 폴더에서는 해당 코드를 확인하지 못했다. 재사용 가능성을 전제로 구현 범위를 잡지 않는다.

## 첫 시나리오

가상의 3D 지형에 활주로, 건물 몇 개, 식별자만 가진 이동 객체 3개를 배치한다. 2~3분짜리 고정 타임라인을 사용하며 실제 비행 성능이나 센서 물리를 모델링하지 않는다. 첫 버전의 시뮬레이션 범위는 3D 위치·이동·시간·관측 이벤트 재생이다.

1. 시작하면 가상 운영 일정과 합성 관측 목록을 표시한다.
2. 객체 하나를 선택하면 관측 출처와 시각을 보여준다.
3. 같은 장면을 아래 세 가지 정보 조건으로 재생한다.
4. 에이전트는 관련 기록을 조회하고 근거 요약과 추가 확인 항목을 작성한다.
5. 사용자는 `검토 완료`, `추가 확인`, `판단 보류` 중 하나를 선택하고 기록을 남긴다.
6. 같은 관측 스냅샷을 다른 에이전트 구성에 제공하고 결과를 비교한다.

| 갈래 | 입력 변화 | 기대 결과 |
| --- | --- | --- |
| 일치 | 두 합성 관측 기록의 정보가 일치 | 일치하는 항목과 출처를 설명하되 객체의 의도나 위험성을 단정하지 않음 |
| 충돌 | 같은 시각의 두 기록에 서로 다른 값이 들어옴 | 상충하는 항목을 함께 제시하고 추가 확인 필요 표시 |
| 결측 | 관측 채널 하나의 갱신이 중단됨 | 마지막 갱신 시각, 누락 출처, 판단할 수 없는 항목 표시 |

객체 종류 확인과 적대성 판단은 구분한다. 출처 하나의 확인 결과를 전체 상황에 대한 확신으로 확대하지 않는다. 보정되지 않은 확신도 백분율은 표시하지 않는다.

## 3D 화면 구성

- 중앙: 가상 비행장과 이동 객체. 전체 조망과 선택 객체 추적 시점을 제공한다.
- 왼쪽: 시나리오 갈래, 관측 채널 상태, 재생 제어.
- 오른쪽: 선택 객체의 관측 기록, 근거 카드, 사람의 검토 입력.
- 하단: 사건 타임라인과 에이전트 도구 호출·완료 상태. 비공개 추론 과정 대신 조회한 근거와 결과를 표시한다.
- 비교 화면: 동일 입력에 대한 구성별 결과, 근거 누락, 응답 시간, 토큰 사용량.

시연자를 위한 전체 장면과 관측 화면을 구분한다. 관측이 끊긴 객체는 관측 화면에서 마지막 관측 위치와 시각으로 표시하며, 제작자만 아는 현재 위치를 관측 사실처럼 보여주지 않는다. 전체 장면은 제작자 보기임을 명시한다.

## 구성과 책임

| 구성 | 책임 |
| --- | --- |
| Godot 4 및 GDScript | 3D 장면, 카메라, 이동 보간, 객체 선택, 재생 제어, 근거 카드와 실험 비교 UI |
| Python 시나리오 코어 | 공식 시뮬레이션 시각, 고정 이벤트, 현재 상태, 정보 품질 규칙 |
| Python API 계층 | Godot와 JSON 메시지를 교환하고 재접속 시 현재 스냅샷 제공 |
| Deep Agents | 관측·맥락·기록 조회 도구를 사용해 설명과 추가 확인 항목 작성 |
| 로컬 JSON 및 JSONL | 시나리오 입력, 이벤트·검토 로그, 에이전트 실행 설정과 결과 |

Python을 상태의 단일 기준으로 두고 Godot는 해당 상태를 표현한다. Godot의 프레임 갱신과 LLM 호출을 분리한다. 시작·일시정지·갈래 선택 등의 명령과 상태 이벤트는 WebSocket으로 교환하는 방안을 우선 고려한다. API 프레임워크와 패키지 버전은 구현 단계에서 확정한다.

Deep Agents는 LangChain 기반이며 LangGraph 런타임을 사용하므로, 처음부터 별도의 복잡한 LangGraph 흐름을 추가할 필요는 없다. 먼저 단일 에이전트로 연결을 검증한 뒤 역할을 나눈 구성을 추가한다. 두 구성을 비교하는 기능까지 첫 결과물에 포함한다.

에이전트가 할 일은 단순 문장 재작성에 그치지 않는다. 선택 객체의 관측 기록을 조회하고, 관련 일정을 찾고, 어떤 자료가 빠졌는지 정리하여 근거가 연결된 카드를 작성한다. 정보 충돌·결측 상태와 최종 검토 기록은 프로그램이 관리하며 에이전트가 변경하지 않는다.

## 에이전트 실험

| 구성 | 역할 | 비교 목적 |
| --- | --- | --- |
| 규칙 기반 기준선 | 정보 상태와 정해진 문구 표시 | LLM 없이도 보장되는 동작 확인 |
| 단일 에이전트 | 관측과 맥락 조회 후 설명 작성 | 최소 구성의 설명 품질과 응답 시간 측정 |
| 역할 분담 구성 | 설명 담당이 맥락 조회·근거 검토 담당에 작업을 위임하고 결과 취합 | 역할 분리가 근거 누락을 줄이는지, 시간과 사용량이 얼마나 늘어나는지 측정 |

역할 분담 구성은 최대 세 역할로 제한한다. 맥락 담당은 합성 일정과 공지의 관련 부분을 찾고, 근거 검토 담당은 설명에 인용된 자료와 누락·충돌 여부를 점검한다. 검토 에이전트의 결과도 검증 대상이며 최종 정답으로 취급하지 않는다. 규칙 검사는 별도 프로그램으로 유지한다.

실험은 객체 단위 자율 행동이 아니라 동일 관측 자료에 대한 설명 작성 작업을 비교한다. 고정한 입력 스냅샷과 읽기 전용 도구 데이터에 각 구성을 실행한다. 실행 중 흘러가는 최신 상태를 읽어서 서로 다른 입력을 받지 않도록 한다.

- 세 갈래 × 세 구성의 비교표를 만들고, LLM 구성은 동일 조건에서 반복 실행해 결과 변동을 기록한다.
- 모델과 설정, 프롬프트 버전, 입력 ID, 호출 제한, 시간 제한, 실제 호출 수를 함께 기록한다. 역할 분담 구성의 사용량은 모든 하위 호출을 합산한다.
- 프로그램으로 필수 필드, 유효한 근거 ID, 오래된 응답 처리를 검사한다.
- 미리 작성한 시나리오별 체크리스트로 중요한 충돌·누락을 언급했는지, 근거 없는 단정이 있는지 사람이 검토한다. 평가용 체크리스트는 에이전트 입력에 포함하지 않는다.
- 설명 품질과 전체 응답 시간·토큰 사용량을 나란히 표시한다. 다중 에이전트 구성이 더 낫다고 미리 가정하지 않는다.

## 구현할 때 지킬 경계

- 에이전트에는 합성 관측과 공개된 시나리오 맥락만 전달한다. 제작자용 정답·향후 이벤트는 전달하지 않는다.
- 이벤트마다 실행 ID, 시뮬레이션 시각, 상태 버전을 붙인다. 재시작 전 또는 이전 상태에 대한 늦은 응답은 최신 카드로 표시하지 않는다.
- LLM 요청은 중요한 이벤트나 사용자 요청 시 실행한다. 객체마다 매 프레임 호출하지 않는다.
- 카드의 근거 ID가 실제 입력에 존재하는지 검증한다. 사실과 근거의 의미상 일치도 별도 검토 대상으로 남긴다.
- LLM 실패 시 규칙 기반 정보 상태를 유지하고 설명 생성 실패를 표시한다. 기록된 응답으로 재생할 때는 재생 모드임을 표시한다.
- 시나리오 재현성과 LLM 응답 재현성을 구분한다. 동일 이벤트의 재생을 보장하고 당시 응답은 로그로 보존한다.

## 구현 순서와 완료 조건

1. **데이터셋과 에셋:** 장면·관측·맥락·평가 정답을 분리하고, 에셋 출처·라이선스·크기·피벗을 기록한다. 단순 도형은 임시 연결 검증에 사용하고 외부 모델과 재질을 포함해 시각 품질을 높인다.
2. **고정 시나리오와 규칙:** 세 갈래 입력으로 정보 상태가 기대대로 달라지는지 자동 검증한다.
3. **Godot 3D 데모:** 장면과 카메라를 만들고 시작·일시정지·재시작, 객체 선택, 세 갈래 전환과 상태 표시를 직접 확인한다.
4. **단일 에이전트 연결:** 근거 조회 도구와 카드 출력을 연결하고 누락 근거, 시간 초과, 오래된 응답을 검증한다.
5. **역할 분담 구성과 비교:** 고정 입력에 대해 세 구성을 실행하고 결과·검토 지표·사용량을 비교 화면에 표시한다.
6. **검토 기록과 재생:** 사람의 검토 결과를 7개 필드로 저장하고 원래 이벤트 및 설명과 함께 재생한다.

7개 필드는 관찰 내용, 고려한 출처, 검토 필요 사유, 뒷받침하는 근거, 불확실한 내용, 적용 맥락 및 제약, 사람의 검토 결과다. 실행 ID와 시각 등은 별도 메타데이터로 둔다.

첫 MVP는 3D 장면에서 세 갈래를 끝까지 재생하고, 기대 정보 상태가 일치하며, 세 구성의 비교 결과를 저장·조회할 수 있어야 한다. 결측이 새 확인 근거로 처리되지 않고, LLM 장애에도 시뮬레이션과 검토 기록이 동작해야 한다. 분류 기능을 제외했으므로 원문의 위협 분류 precision/recall을 성능 지표로 사용하지 않는다. 이 데모의 통과는 실제 센서 성능이나 운용 적합성을 입증하지 않는다.

## 미확정 사항

- 구현 인원과 목표 일정: 원문의 24시간을 현재 일정으로 가정하지 않음
- 사용할 LLM 제공자와 실행 환경
- 목표 장비·프레임 속도·최종 에셋 예산: 실사 지향은 확정했으며 세부 성능 목표는 미정

주요 구현 부담은 3D 자산 제작과 다중 에이전트의 응답 시간·사용량이다. 첫 장면은 간단한 도형으로 완성하고, 에이전트 실행은 시뮬레이션 갱신과 분리한다. 모델 없이 실행되는 기준선과 기록 재생도 제공한다.

## 현재 준비된 자료

`data/scenarios/v1`에 합성 데이터 12개 케이스, 관측 324건, 평가 체크포인트 144개를 구성했다. 개발용·보류 평가용을 기본 장면 단위로 나눴고, 에이전트 입력에서 미래 기록과 평가 정보를 제외하는 추출기를 제공한다. 같은 생성 규칙의 작은 변형이므로 일반화 성능을 입증하는 평가셋은 아니다.

`godot`에는 임시 GLB 7종, 비교용 Kenney 모델 4종, 상세 격납고·관제탑·보조 건물과 가상 지형을 준비했다. 기본 화면에는 Poly Haven PBR 재질 4세트와 HDRI, Cesium 항공기 샘플을 연결했다. 최종 미술 완성본은 아니며 항공기는 교체 가능한 시각 샘플이다. 관측 채널 2개와 이동 객체 3개를 재생하며, 에셋 ID를 통해 모델 교체와 시나리오 내용을 분리한다. 현재 화면은 제작자 보기이고 최종 관측 UI 및 에이전트는 아직 연결하지 않았다. 출처와 라이선스는 외부 모델 폴더에 보관했다.
